# Безопасность

## Как сообщить об уязвимости

Не открывайте публичный issue. Напишите правообладателю на
letenkovmaksim@yandex.ru (тема — `bisquite-teleport-agent security`) или
используйте GitHub Security Advisories этого репозитория («Report a
vulnerability»). Укажите версию пакета (`bisquite-teleport version`), шаги
воспроизведения и что именно удаётся сделать. Ответ — в течение 7 дней.

Поддерживается последняя выпущенная версия; исправления выходят новым
патч-релизом с `SHA256SUMS`.

## Модель доверия

- `teleport` и `bisquite-teleport` работают от root: агент открывает
  SSH-сессии под любым логином, разрешённым ролями кластера.
- **Портал меток** (`/robot-api/v1/labels`) может менять только `space` и
  `env` — два значения из алфавита метки DNS; ответ проверяется целиком до
  записи (форма, порядок ключей, ≤ 4096 байт, без NUL). Код на машину через
  этот канал не доставляется, но смена `space`/`env` переносит машину между
  пространствами доступа: портал — корень доверия для доступа к машине.
- **Токен меток** и **токен/секрет регистрации** не попадают в argv и журнал:
  stdin или файл 0600, заголовок `curl` — из файла (`-H @файл`). Токен
  регистрации и секрет `bound_keypair` стираются после регистрации.
- **Объявления `apps.d`** принимаются только от root, с правами не шире
  `0644`, не символической ссылкой, с адресом на петле; метку доступа
  объявление задать не может.
- **Пакет** ставится по пину sha256 (`SHA256SUMS` релиза, пин в обёртке
  bisquite-extensions или в зеркале портала). Подписи релизов пока нет.
